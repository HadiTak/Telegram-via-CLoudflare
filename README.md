# TG Relay — پروکسی تلگرام از طریق Cloudflare Worker

ساختار پروژه تا حد امکان تخت (flat) شده تا آپلود دستی توی گیت‌هاب راحت باشه.
همه‌چیز مستقیم توی شاخه‌ی اصلیه، فقط دو پوشه اجباری باقی مونده:
- `res/` (چون آندروید ساختار res/layout و res/values رو الزامی می‌کنه)
- `.github/workflows/` (چون GitHub Actions فقط از این مسیر دقیق ورک‌فلو رو می‌خونه)

---

## مرحله ۱: دیپلوی Worker روی Cloudflare

1. یه اکانت رایگان در https://dash.cloudflare.com بسازید.
2. `Compute` → `Workers & Pages` → `Create Application` → `Start with Hello World!` → `Deploy`.
3. `Edit code` رو بزنید و کل کد پیش‌فرض رو با محتوای فایل `cloudflare-worker.js` جایگزین کنید → `Deploy`.
4. آدرس Worker (مثل `random-name.your-username.workers.dev`) رو کپی کنید.
5. **مهم — تنظیم کلید مشترک:** بدون این مرحله، هرکسی که آدرس Worker رو پیدا کنه می‌تونه ازش مجانی به‌عنوان پروکسی استفاده کنه و اعتبار شما رو مصرف کنه.

   ⚠️ **نکته‌ی مهم:** کلید رو **داخل فایل `cloudflare-worker.js` تایپ نمی‌کنید.** کد فقط با `env.AUTH_KEY` بهش رفرنس می‌ده؛ مقدار واقعی رو جدا و از طریق پنل Cloudflare (نه داخل کد) تعریف می‌کنید — این‌جوری اگه یه روز کد Worker رو با کسی به اشتراک بذارید، کلید لو نمی‌ره. مراحل دقیق:

   1. یه رشته‌ی تصادفی و طولانی بسازید (مثلاً با اجرای `openssl rand -hex 32` توی ترمینال، یا هر تولیدکننده‌ی رمز آنلاین).
   2. برید توی داشبورد Cloudflare → `Workers & Pages` → روی Worker خودتون کلیک کنید → تب `Settings`.
   3. توی همون صفحه، بخش `Variables and Secrets` رو پیدا کنید → `Add`.
   4. Type: `Secret` — Name: دقیقاً `AUTH_KEY` (حروف بزرگ، بدون فاصله) — Value: همون رشته‌ی تصادفی.
   5. `Deploy` رو بزنید.
   6. همین رشته رو دقیقاً (بدون فاصله‌ی اضافه، بدون enter اضافه) بعداً توی اپ اندروید، فیلد «کلید مشترک» وارد می‌کنید. جایی امن نگهش دارید.

---

## مرحله ۲: ساخت ریپازیتوری و آپلود

1. توی گیت‌هاب یه ریپازیتوری خالی جدید بسازید (بدون README/gitignore).
2. توی صفحه‌ی ریپوی خالی، لینک «uploading an existing file» رو بزنید.
3. از پوشه‌ی استخراج‌شده‌ی این پروژه، همه‌چیز رو انتخاب و بکشید تو صفحه:
   `build.gradle`, `settings.gradle`, `gradle.properties`, `AndroidManifest.xml`,
   `cloudflare-worker.js`, `README.md`، و پوشه‌های `res` و `src` (با محتواشون — پوشه‌ی `res` الان شامل زیرپوشه‌های `mipmap-*` هم می‌شه که آیکن اپ توشونه).
   چون همه‌چیز الان تخته، این کار با یه drag & drop انجام می‌شه.
4. «Commit changes» رو بزنید.
5. پوشه‌ی مخفی `.github` با درگ-دراپ آپلود نمی‌شه؛ پس دستی بسازیدش:
   `Add file → Create new file` → توی اسم فایل دقیقاً بنویسید: `.github/workflows/build-apk.yml`
   محتوای فایل `.github/workflows/build-apk.yml` (همینجا در پروژه هست) رو کپی و پیست کنید → `Commit changes`.

(راه جایگزین سریع‌تر: استفاده از دستورات `git` که همه‌چیز از جمله `.github` رو یکجا آپلود می‌کنه — `git init && git add . && git commit -m "init" && git remote add origin <repo-url> && git push -u origin main`.)

---

## مرحله ۳: اجرای Build و دانلود apk

1. تب `Actions` رو باز کنید — چون به `main` پوش کردید، ورک‌فلو خودش اجرا می‌شه (یا دستی `Run workflow` بزنید).
2. حدود ۳ تا ۷ دقیقه صبر کنید تا تیک سبز ✅ بخوره.
3. روی همون run کلیک کنید، پایین صفحه بخش `Artifacts` یه فایل به اسم `TGRelay-arm64-v8a-debug` هست — دانلودش کنید.
4. زیپش رو باز کنید، یه فایل `.apk` توشه. اون رو روی گوشی منتقل و نصب کنید (نیاز به اجازه‌ی «نصب از منابع ناشناس»).

apk فقط برای معماری `arm64-v8a` ساخته می‌شه.

---

## مرحله ۴: استفاده

1. اپ رو باز کنید، آدرس Worker رو وارد کنید (بدون `https://`، فقط مثل `xxxx.username.workers.dev`).
2. پورت رو `1080` بذارید (یا دلخواه).
3. کلید مشترک رو دقیقاً همون چیزی که در `AUTH_KEY` روی Cloudflare ست کردید وارد کنید.
4. «فعال کردن» رو بزنید. اپ اول یه تست سریع به Worker می‌زنه («در حال بررسی...») و اگه کلید یا آدرس غلط باشه، **همون‌جا** یه پیام خطای واضح نشون می‌ده و فعال نمی‌شه — دیگه لازم نیست منتظر بمونید تا توی تلگرام معلوم بشه.
5. اگه همه‌چیز درست بود، وضعیت می‌شه «فعال ✅» و دکمه‌ی «باز کردن در تلگرام و ست کردن پروکسی» فعال می‌شه — بزنیدش، دیالوگ SOCKS5 با مقادیر پرشده باز می‌شه، فقط تأیید کنید.
6. اگه دکمه کار نکرد، دستی: `Settings → Data and Storage → Proxy → Add Proxy → SOCKS5` → Server: `127.0.0.1` → Port: همون پورت.

برای خاموش کردن، دکمه «غیرفعال کردن» رو توی اپ و پروکسی رو توی تلگرام خاموش کنید.

## نکات

- این روش فقط ترافیک تلگرام رو عبور می‌ده (نه کل گوشی رو) — باتری و دیتای بقیه‌ی اپ‌ها درگیر نمی‌شه.
- اگه `workers.dev` هم فیلتر شد، باید یه دامنه‌ی شخصی روی Cloudflare ثبت کنید.
- **مهم:** یه padding تصادفی کوچیک (۰ تا ۶۳ بایت) به هر بسته روی لینک اپ↔Worker اضافه شده تا اندازه‌ی بسته‌ها نامنظم بشه و شناسایی الگوی MTProto سخت‌تر بشه. این تغییر روی **هر دو طرف** (هم کد Worker، هم اپ) با هم اعمال شده — اگه فقط یکی رو آپدیت کنید و اون یکی رو نه، اتصال کار نمی‌کنه. پس حتماً هر دو رو با هم دوباره دیپلوی/بیلد کنید.
- اپ قبل از فعال شدن یه درخواست به مسیر `/check` روی Worker می‌زنه تا کلید رو تست کنه؛ این مسیر هم توی کد Worker هست، پس اگه از یه نسخه‌ی قدیمی‌تر Worker استفاده می‌کنید، حتماً آپدیتش کنید وگرنه تست کلید با خطای ۴۰۴ مواجه می‌شه.
- **اگه تلگرام روی «Connecting» گیر کرد** (با اینکه فعال‌سازی توی اپ موفق بود): این یعنی WebSocket بین اپ و Worker برقرار شده ولی اتصال TCP بین Worker و سرور تلگرام مشکل داره. برای دیباگ:
  1. توی داشبورد Cloudflare، برید `Workers & Pages` → روی Worker خودتون کلیک کنید → تب `Logs`.
  2. `Begin log stream` (یا دکمه‌ی مشابه برای لاگ زنده) رو بزنید.
  3. توی اپ، دکمه‌ی «فعال کردن» رو بزنید و بعد سعی کنید توی تلگرام وصل بشید.
  4. هر خطایی که توی لاگ زنده ظاهر شد (مخصوصاً خط‌هایی که با `tcp connect failed` یا `tcp read failed` شروع می‌شن) رو کپی کنید و برام بفرستید — از روش می‌فهمم دقیقاً کجای اتصال گیر کرده.
- هیچ روش obfuscationـی (نه این یکی، نه هیچ ابزار دیگه‌ای) تضمین صددرصدی در برابر فیلترینگ پیشرفته نمی‌ده؛ فقط سطح شناسایی رو سخت‌تر می‌کنه. محتوای واقعی از قبل هم داخل TLS رمزنگاری شده بود.
- اگه لاگ خطای Actions گرفتید، متنشو بفرستید تا دقیق بگم مشکل کجاست.
