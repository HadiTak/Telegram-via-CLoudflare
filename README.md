# TG Relay

پروکسی تلگرام که ترافیک رو از طریق یک Cloudflare Worker عبور می‌ده تا از فیلترینگ عبور کنه.
اتصال بین گوشی و Worker روی `wss://` (پورت ۴۴۳، همون پورت HTTPS معمولی) انجام می‌شه، پس از دید فیلترینگ شبیه یک اتصال HTTPS عادیه.

---

## فهرست فایل‌های پروژه

```
cloudflare-worker.js   →  کد سمت سرور (روی Cloudflare اجرا می‌شه)
wrangler.toml          →  تنظیمات لازم برای دیپلوی با ابزار Wrangler
AndroidManifest.xml    →  فایل تنظیمات اپ اندروید
MainActivity.kt        →  رابط کاربری اپ
ProxyService.kt         →  منطق اصلی پروکسی (SOCKS5 + اتصال به Worker)
res/                    →  آیکن و layout اپ
build.gradle            →  تنظیمات کامپایل اپ
settings.gradle
gradle.properties
.github/workflows/build-apk.yml → می‌سازه apk رو به‌صورت خودکار
```

---

## بخش ۱: دیپلوی Worker روی Cloudflare

### ۱.۱ ساخت Worker

یک اکانت رایگان بسازید:

```
dash.cloudflare.com
```

سپس مسیر زیر را دنبال کنید:

```
Workers & Pages → Create Application → Start with Hello World! → Deploy
```

### ۱.۲ جایگزین کردن کد

روی دکمه‌ی زیر بزنید:

```
Edit code
```

کل کد پیش‌فرض را پاک کنید و محتوای فایل `cloudflare-worker.js` را کامل جایگزین کنید. سپس:

```
Deploy
```

### ۱.۳ ساخت کلید مشترک (AUTH_KEY)

بدون این کلید، هر کسی که آدرس Worker شما را پیدا کند می‌تواند مجانی از آن استفاده کند و اعتبار شما را مصرف کند.

اگر روی کامپیوتر (لینوکس یا مک) دسترسی به ترمینال دارید، یک رشته‌ی تصادفی امن با این دستور بسازید:

```
openssl rand -hex 32
```

اگر ترمینال ندارید، هر ابزار آنلاین «random hex string generator» هم کافیست — یک رشته‌ی حداقل ۳۲ کاراکتری بسازید.

### ۱.۴ ثبت کلید در تنظیمات Worker

در پنل Worker خودتان به این مسیر بروید:

```
Settings → Variables and Secrets → Add
```

سپس مقادیر زیر را وارد کنید:

```
Type:  Secret
Name:  AUTH_KEY
Value: (همان رشته‌ی تصادفی که ساختید)
```

در پایان:

```
Deploy
```

این رشته را جایی امن نگه دارید — دقیقاً همین مقدار را بعداً باید داخل خود اپ اندروید هم وارد کنید.

## بخش ۲: فعال کردن Durable Object (برای پایداری اتصال)

یک Worker معمولی Cloudflare برای اتصال‌های طولانی‌مدت طراحی نشده و بعد از حدود ۳۰ ثانیه اتصال را قطع می‌کند. برای این‌که تلگرام بتواند یک اتصال پایدار داشته باشد، این پروژه از یک Durable Object (کلاس `Relay` در همان فایل `cloudflare-worker.js`) استفاده می‌کند.

این بخش را **فقط با ابزار Wrangler** می‌توان تنظیم کرد؛ ادیتور ساده‌ی داخل مرورگر (Quick Edit) این قابلیت را ندارد.

اگر با نصب Node.js و اجرای دستورات ترمینال راحت هستید، مراحل زیر را دنبال کنید. (اگر خودتان روش دیگری برای دیپلوی با Wrangler دارید، همین‌جا فقط کافیست از فایل `wrangler.toml` استفاده کنید — تنظیمات لازم از قبل در آن نوشته شده.)

### ۲.۱ نصب Node.js

از سایت رسمی نصب کنید:

```
nodejs.org
```

### ۲.۲ ورود به پوشه‌ی پروژه

پوشه‌ی این پروژه (همان‌جایی که فایل `wrangler.toml` قرار دارد) را در ترمینال باز کنید:

```
cd path/to/TGRelay
```

### ۲.۳ ورود به حساب Cloudflare

```
npx wrangler login
```

یک صفحه‌ی مرورگر باز می‌شود؛ اجازه‌ی دسترسی را تایید کنید.

### ۲.۴ دیپلوی نهایی

```
npx wrangler deploy
```

این دستور همزمان کد را دیپلوی می‌کند و Durable Object (کلاس `Relay`) را هم فعال می‌کند. اسم Worker در `wrangler.toml` از قبل تنظیم شده تا همان Worker قبلی‌تان آپدیت شود، نه یک Worker جدید ساخته شود.

> نکته: هر بار که فایل `cloudflare-worker.js` تغییر کرد، فقط کافیست دوباره همین دستور را اجرا کنید:
> ```
> npx wrangler deploy
> ```

## بخش ۳: ساخت apk اپ اندروید

apk به‌صورت خودکار توسط GitHub Actions ساخته می‌شود، بدون نیاز به نصب Android Studio.

### ۳.۱ ساخت ریپازیتوری در گیت‌هاب

یک ریپازیتوری خالی جدید بسازید (بدون تیک زدن README یا gitignore).

### ۳.۲ آپلود پروژه

ساده‌ترین راه استفاده از دستورات Git است (چون پوشه‌ی مخفی `.github` را هم کامل منتقل می‌کند):

```
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

آدرس `USERNAME/REPO.git` را با آدرس واقعی ریپوی خودتان جایگزین کنید.

### ۳.۳ اجرای Build

به تب زیر در ریپو بروید:

```
Actions
```

ورک‌فلوی زیر باید خودکار اجرا شده باشد (یا دستی با دکمه‌ی Run workflow اجرایش کنید):

```
Build APK
```

بعد از اتمام (چند دقیقه)، در پایین همان صفحه‌ی run:

```
Artifacts → TGRelay-arm64-v8a-debug
```

را دانلود کنید. داخل آن یک فایل apk قابل نصب است. این apk فقط برای معماری `arm64-v8a` ساخته می‌شود (اکثر گوشی‌های امروزی).

apk را روی گوشی منتقل و نصب کنید (نیاز به فعال کردن «نصب از منابع ناشناس» دارید).

## بخش ۴: استفاده از اپ

اپ را باز کنید و مقادیر زیر را وارد کنید:

- کلید مشترک: همان مقداری که در بخش ۱.۳ ساختید
- آدرس Worker: بدون `https://` و بدون `/apiws`، فقط چیزی شبیه:
  ```
  example.username.workers.dev
  ```
- پورت: پیش‌فرض `1080` را می‌توانید نگه دارید

سپس:

1. دکمه‌ی «فعال کردن» را بزنید. اپ ابتدا یک تست سریع می‌زند («در حال بررسی…»)؛ اگر کلید یا آدرس اشتباه باشد، همان‌جا خطای مشخص نشان می‌دهد.
2. وقتی وضعیت «فعال ✅» شد، دکمه‌ی «باز کردن در تلگرام و ست کردن پروکسی» را بزنید — دیالوگ افزودن پروکسی SOCKS5 در تلگرام با مقادیر پرشده باز می‌شود، فقط تایید کنید.
3. اگر دکمه کار نکرد، به‌صورت دستی در تلگرام:
   ```
   Settings → Data and Storage → Proxy → Add Proxy → SOCKS5
   Server: 127.0.0.1
   Port: (همان پورتی که در اپ گذاشتید)
   ```

برای خاموش کردن، دکمه‌ی «غیرفعال کردن» را در اپ و پروکسی را در تلگرام خاموش کنید.

## نکات فنی

- ترافیک واقعی MTProto قبل از ارسال، با یک padding تصادفی کوچک (۰ تا ۶۳ بایت) پوشانده می‌شود تا اندازه‌ی بسته‌ها نامنظم شود و شناسایی الگوی پروتکل سخت‌تر شود. این padding فقط روی لینک اپ↔Worker اضافه می‌شود و قبل از رسیدن واقعی به سرور تلگرام حذف می‌شود.
- این پروکسی فقط ترافیک تلگرام را عبور می‌دهد (نه کل گوشی را)، پس باتری و دیتای بقیه‌ی اپ‌ها درگیر نمی‌شود.
- اگر یک روز `workers.dev` هم فیلتر شد، باید یک دامنه‌ی شخصی روی Cloudflare ثبت کنید و به‌جای آن استفاده کنید.
- اگر حس کردید کلید `AUTH_KEY` لو رفته، فقط کافیست مقدارش را در بخش ۱.۴ عوض کنید (نیازی به دیپلوی مجدد کل کد یا تغییر آدرس Worker نیست) و همان مقدار جدید را در اپ هم به‌روزرسانی کنید.

## عیب‌یابی

اگر تلگرام روی «Connecting» ماند یا خطایی گرفتید، لاگ زنده‌ی Cloudflare را باز کنید:

```
Workers & Pages → (نام Worker شما) → Logs → Begin log stream
```

سپس دوباره در اپ «فعال کردن» را بزنید و در تلگرام سعی کنید وصل شوید. هر خطایی که در لاگ ظاهر شد را کپی کنید تا بررسی شود.
