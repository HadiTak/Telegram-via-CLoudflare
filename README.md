# TG Relay

پروکسی اختصاصی تلگرام برای عبور از فیلترینگ، با استفاده از یک Cloudflare Worker به‌عنوان واسطه.
ترافیک تلگرام از طریق یک اتصال WebSocket رمزنگاری‌شده (`wss://`) به یک دامنه‌ی `workers.dev` می‌رود —
از دید فیلترینگ، دقیقاً شبیه یک اتصال HTTPS عادی به Cloudflare است.

---

## این پروژه چطور کار می‌کند؟

```
تلگرام (روی گوشی)
   ↓  (پروکسی SOCKS5 روی 127.0.0.1)
اپ TG Relay
   ↓  (WebSocket رمزنگاری‌شده، پورت 443)
Cloudflare Worker
   ↓  (اتصال TCP خام)
سرورهای واقعی تلگرام
```

- اپ اندروید یک سرور SOCKS5 محلی روی خود گوشی بالا می‌آورد.
- تلگرام (با تنظیم پروکسی SOCKS5 در خودش) به این سرور محلی وصل می‌شود.
- هر بایتی که تلگرام می‌فرستد، اپ آن را از طریق یک اتصال WebSocket به یک Cloudflare Worker می‌فرستد.
- Worker یک اتصال TCP خام به سرور واقعی تلگرام باز می‌کند و داده‌ها را در هر دو جهت رد و بدل می‌کند.
- یک لایه‌ی padding تصادفی هم اضافه شده تا اندازه‌ی بسته‌ها نامنظم شود و شناسایی الگوی پروتکل تلگرام سخت‌تر شود.
- برای جلوگیری از سوءاستفاده‌ی دیگران از آدرس Worker شما، یک کلید مشترک (`AUTH_KEY`) بین اپ و Worker رد و بدل می‌شود.

---

## ساختار فایل‌های پروژه

| فایل / پوشه | توضیح |
|---|---|
| `cloudflare-worker.js` | کد Worker (شامل کلاس Durable Object به اسم `Relay`) |
| `wrangler.toml` | تنظیمات دیپلوی Worker (نام اسکریپت، Durable Object binding) |
| `AndroidManifest.xml` | مانیفست اپ اندروید |
| `build.gradle`, `settings.gradle`, `gradle.properties` | فایل‌های Gradle برای بیلد اپ |
| `src/MainActivity.kt` | صفحه‌ی اصلی اپ (فرم تنظیمات، دکمه‌ها) |
| `src/ProxyService.kt` | سرویس پس‌زمینه (سرور SOCKS5 محلی + ارتباط با Worker) |
| `res/layout/activity_main.xml` | چیدمان صفحه‌ی اصلی |
| `res/mipmap-*` | آیکن اپ در سایزهای مختلف |
| `.github/workflows/build-apk.yml` | GitHub Actions برای ساخت apk |
| `.github/workflows/deploy-worker.yml` | GitHub Actions برای دیپلوی Worker با Wrangler |

## مرحله ۱: ساخت Worker پایه در Cloudflare

۱. یک اکانت رایگان در آدرس زیر بسازید:

```
https://dash.cloudflare.com
```

۲. از منوی سمت چپ مسیر زیر را دنبال کنید:

```
Compute
→ Workers & Pages
→ Create Application
→ Start with Hello World!
→ Deploy
```

۳. بعد از دیپلوی اولیه، اسم Worker خودتان را یادداشت کنید (مثلاً `tgviaandroid`) —
همین اسم باید بعداً در فایل `wrangler.toml` استفاده شود تا دیپلوی بعدی همین Worker را آپدیت کند، نه یک Worker جدید بسازد.

> ⚠️ **نکته‌ی مهم:** ادیتور ساده‌ی داخل داشبورد Cloudflare (Quick Edit) نمی‌تواند Durable Object جدید بسازد،
> چون این کار به یک migration نیاز دارد که فقط از طریق Wrangler ممکن است.
> برای همین، دیپلوی نهایی کد Worker را در مرحله‌ی ۴ با GitHub Actions انجام می‌دهیم، نه با کپی‌پیست دستی در داشبورد.

## مرحله ۲: ساخت و تنظیم کلید مشترک (AUTH_KEY)

بدون این مرحله، هر کسی که آدرس Worker شما را پیدا کند می‌تواند مجانی از آن به‌عنوان پروکسی استفاده کند.

۱. یک رشته‌ی تصادفی و طولانی بسازید. ساده‌ترین راه: داخل خود اپ اندروید،
دکمه‌ی «ساخت کلید تصادفی و کپی» را بزنید — یک کلید امن می‌سازد و آن را کپی می‌کند.

۲. در داشبورد Cloudflare، وارد تنظیمات همان Worker شوید و این مسیر را دنبال کنید:

```
Settings
→ Variables and Secrets
→ Add
```

۳. مقادیر زیر را وارد کنید:

```
Type: Secret
Name: AUTH_KEY
Value: (همان کلیدی که کپی کردید)
```

۴. دکمه‌ی Deploy را بزنید.

۵. همین مقدار را بعداً در اپ اندروید، داخل فیلد «کلید مشترک»، دقیقاً همین‌طور (بدون فاصله‌ی اضافه) وارد می‌کنید.

> اگر یک روز حس کردید این کلید لو رفته، کافی است فقط مقدار `AUTH_KEY` را در همین صفحه عوض کنید و در اپ هم آپدیت کنید —
> نیازی به ساختن Worker جدید یا تغییر آدرس نیست.

## مرحله ۳: ساخت ریپازیتوری در گیت‌هاب

۱. یک ریپازیتوری جدید و خالی بسازید (بدون افزودن README یا gitignore).

۲. برای آپلود همه‌ی فایل‌های این پروژه، ساده‌ترین و مطمئن‌ترین راه استفاده از دستورات `git` است
(چون شامل فایل مخفی `.github` هم می‌شود که با درگ‌ودراپ معمولی آپلود نمی‌شود):

```
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

آدرس `USERNAME/REPO.git` را با آدرس واقعی ریپوی خودتان جایگزین کنید.

> اگر گیت‌هاب موقع push به‌جای پسورد چیزی خواست: پسورد معمولی دیگر قبول نمی‌شود.
> باید یک Personal Access Token بسازید:
>
> ```
> Settings
> → Developer settings
> → Personal access tokens
> → Tokens (classic)
> → Generate new token
> ```
>
> دسترسی `repo` را تیک بزنید و رشته‌ی تولیدشده را به‌جای پسورد وارد کنید.

## مرحله ۴: افزودن Secretها به گیت‌هاب (برای دیپلوی خودکار Worker)

برای اینکه GitHub Actions بتواند از طرف شما Worker را با Wrangler دیپلوی کند، دو مقدار لازم است.

### ساخت API Token در Cloudflare

۱. به این آدرس بروید:

```
https://dash.cloudflare.com/profile/api-tokens
```

۲. دکمه‌ی Create Token را بزنید و تمپلیت زیر را انتخاب کنید:

```
Edit Cloudflare Workers
```

(اگر این تمپلیت نبود، یک Custom Token با دسترسی زیر بسازید: `Account → Workers Scripts → Edit`)

۳. رشته‌ی نمایش داده‌شده را کپی کنید — فقط یک بار نشان داده می‌شود.

### پیدا کردن Account ID

در داشبورد Cloudflare، صفحه‌ی هر کدام از اکانت‌ها (مثلاً Workers & Pages) را باز کنید؛
یک شناسه‌ی ۳۲ کاراکتری با اسم **Account ID** در همان صفحه دیده می‌شود — آن را کپی کنید.

### افزودن به گیت‌هاب

در صفحه‌ی ریپوی خودتان، این مسیر را دنبال کنید:

```
Settings
→ Secrets and variables
→ Actions
→ New repository secret
```

دو Secret زیر را بسازید:

```
نام: CLOUDFLARE_API_TOKEN
مقدار: همان توکنی که ساختید

نام: CLOUDFLARE_ACCOUNT_ID
مقدار: همان Account ID
```

## مرحله ۵: دیپلوی Worker با GitHub Actions

۱. مطمئن شوید فایل‌های `cloudflare-worker.js` و `wrangler.toml` در ریپوی شما push شده باشند.

۲. در صفحه‌ی ریپو، این مسیر را دنبال کنید:

```
Actions
→ Deploy Cloudflare Worker
```

۳. اگر خودکار اجرا نشد، دکمه‌ی Run workflow را بزنید.

۴. بعد از موفقیت (تیک سبز)، به داشبورد Cloudflare برگردید و همان Worker قبلی را باز کنید.
حالا اگر به تنظیمات Bindings بروید، باید کلاس `Relay` قابل مشاهده باشد — یعنی Durable Object با موفقیت فعال شده.

## مرحله ۶: ساخت apk با GitHub Actions

۱. در همان ریپو، این مسیر را دنبال کنید:

```
Actions
→ Build APK
```

۲. اگر خودکار اجرا نشد، دکمه‌ی Run workflow را بزنید.

۳. صبر کنید تا تیک سبز بخورد (چند دقیقه طول می‌کشد).

۴. روی همان اجرا (run) کلیک کنید، پایین صفحه بخش **Artifacts** را پیدا کنید،
فایل `TGRelay-arm64-v8a-debug` را دانلود کنید.

۵. زیپ را باز کنید — یک فایل apk داخلش است. آن را روی گوشی منتقل و نصب کنید
(نیاز به اجازه‌ی «نصب از منابع ناشناس» دارید).

apk فقط برای معماری `arm64-v8a` ساخته می‌شود (اکثر گوشی‌های امروزی همین‌طورند).

## مرحله ۷: استفاده از اپ

۱. اپ را باز کنید.

۲. آدرس Worker را وارد کنید — فقط قسمت دامنه، بدون `https://` و بدون `/apiws`:

```
مثال: tgviaandroid.username.workers.dev
```

۳. پورت را روی مقدار پیش‌فرض `1080` بگذارید (یا هر عدد دلخواه دیگر).

۴. کلید مشترک را وارد کنید (همان `AUTH_KEY`) — یا با دکمه‌ی «ساخت کلید تصادفی و کپی» بسازید و بعد در Cloudflare هم ثبتش کنید.

۵. دکمه‌ی «فعال کردن» را بزنید. اپ اول یک تست سریع به Worker می‌زند («در حال بررسی...»)؛
اگر کلید یا آدرس اشتباه باشد، همان‌جا با پیام خطای مشخص متوقف می‌شود.

۶. بعد از رسیدن وضعیت به «فعال ✅»، دکمه‌ی «باز کردن در تلگرام و ست کردن پروکسی» را بزنید —
دیالوگ افزودن پروکسی SOCKS5 با مقادیر پرشده در تلگرام باز می‌شود، فقط تأیید کنید.

اگر آن دکمه کار نکرد، می‌توانید دستی هم اضافه کنید. در تلگرام این مسیر را دنبال کنید:

```
Settings
→ Data and Storage
→ Proxy
→ Add Proxy
→ SOCKS5
```

و مقادیر زیر را وارد کنید:

```
Server: 127.0.0.1
Port: همان پورتی که در اپ گذاشتید (پیش‌فرض 1080)
```

برای خاموش کردن، کافی است دکمه‌ی «غیرفعال کردن» را در اپ بزنید و پروکسی را هم در تلگرام خاموش کنید.

---

## عیب‌یابی

### وقتی «فعال کردن» می‌زنید بلافاصله خطا می‌دهد

- اگر پیام «کلید مشترک اشتباهه» دیدید: مقدار `AUTH_KEY` در اپ و در Cloudflare باید دقیقاً یکی باشند (بدون فاصله‌ی اضافه).
- اگر پیام «آدرس Worker درست نیست» دیدید: مطمئن شوید آدرس را بدون `https://` و بدون `/` اضافه در انتها وارد کرده‌اید.
- اگر پیام «اتصال به Worker برقرار نشد» دیدید: اینترنت گوشی یا صحت آدرس Worker را چک کنید.

### تلگرام روی «Connecting» می‌ماند

۱. مطمئن شوید هم آخرین نسخه‌ی apk نصب شده، هم آخرین نسخه‌ی Worker دیپلوی شده.

۲. لاگ زنده‌ی Cloudflare را باز کنید:

```
Workers & Pages
→ (اسم Worker شما)
→ Logs
→ Begin log stream
```

۳. دوباره در اپ «فعال کردن» را بزنید و در تلگرام سعی کنید وصل شوید.

۴. هر خطایی که در لاگ ظاهر شد را کپی کنید — روی این متن می‌شود دقیق مشکل را پیدا کرد.

### تست سریع کلید بدون اپ

آدرس زیر را (با آدرس واقعی Worker خودتان) در مرورگر باز کنید:

```
https://آدرس-ورکر-شما/check
```

- اگر نوشت `Forbidden`: Worker درست کار می‌کند (چون بدون کلید رفته‌اید، طبیعی است رد کند).
- اگر نوشت `Expected websocket`: نسخه‌ی قدیمی کد روی Worker مانده، دوباره دیپلویش کنید.

## نکات فنی و امنیتی

- ترافیک واقعی تلگرام از ابتدا تا انتها داخل TLS رمزنگاری شده است؛ padding اضافه‌شده فقط اندازه‌ی بسته‌ها را نامنظم می‌کند تا الگوی پروتکل کمتر قابل تشخیص باشد. هیچ روش obfuscationـی تضمین صددرصدی در برابر فیلترینگ پیشرفته نمی‌دهد.
- این روش فقط ترافیک تلگرام را عبور می‌دهد (نه کل گوشی را) — باتری و دیتای بقیه‌ی اپ‌ها درگیر نمی‌شود.
- اگر روزی دامنه‌ی `workers.dev` هم فیلتر شد، باید یک دامنه‌ی شخصی روی Cloudflare ثبت کنید و آن را جایگزین کنید.
- اتصال بین اپ و Worker از طریق یک Durable Object نگه‌داشته می‌شود، چون یک Worker معمولی بعد از حدود ۳۰ ثانیه اتصال طولانی‌مدت را قطع می‌کند — این محدودیت پلتفرم Cloudflare است، نه باگ کد.
- محل اجرای Worker با `locationHint: "me"` به سمت خاورمیانه هدایت شده تا تأخیر رفت‌وبرگشت کمتر باشد؛ این یک best-effort است، نه تضمین قطعی.
