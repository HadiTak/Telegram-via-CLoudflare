# TG Relay

پروکسی شخصی برای عبور تلگرام از فیلترینگ، با استفاده از یک Cloudflare Worker به‌عنوان واسط. تمام ترافیک از طریق یک اتصال رمزنگاری‌شده (`wss://`) به دامنه‌ی Cloudflare می‌ره که از دید فیلترینگ شبیه یک اتصال HTTPS معمولیه.

این پروژه از سه بخش تشکیل شده:

- `cloudflare-worker.js` — کدی که روی Cloudflare اجرا می‌شه و نقش واسط بین اپ و سرورهای تلگرام رو داره
- اپ اندروید (فایل‌های داخل `src/` و `res/`) — یک پروکسی SOCKS5 محلی که تلگرام بهش وصل می‌شه
- `wrangler.toml` و `.github/workflows/` — تنظیمات لازم برای دیپلوی خودکار Worker و ساخت خودکار apk

---

## پیش‌نیازها

- یک اکانت رایگان Cloudflare
- یک اکانت رایگان GitHub
- گوشی اندروید با نسخه ۷ (Android 7) یا بالاتر

---

## مرحله‌ی ۱ — ساخت Cloudflare Worker

۱. وارد این آدرس بشید:

```
https://dash.cloudflare.com
```

۲. مسیر زیر رو دنبال کنید:

```
Workers & Pages → Create Application → Start with Hello World! → Deploy
```

۳. بعد از دیپلوی اولیه، دکمه‌ی `Edit code` رو بزنید. تمام کد پیش‌فرض رو پاک کنید و کل محتوای فایل `cloudflare-worker.js` (همین پروژه) رو جایگزینش کنید. سپس `Deploy` بزنید.

۴. آدرس Worker رو یادداشت کنید، چیزی شبیه این:

```
tgviaandroid.your-username.workers.dev
```

این آدرس رو بعداً داخل اپ وارد می‌کنید (بدون `https://` و بدون `/apiws`).

---

## مرحله‌ی ۲ — ساخت کلید مشترک (AUTH_KEY)

بدون این مرحله، هرکسی آدرس Worker رو پیدا کنه می‌تونه ازش مجانی استفاده کنه و اعتبار شما رو مصرف کنه.

نکته‌ی مهم: کلید هیچ‌وقت داخل خود فایل `cloudflare-worker.js` نوشته نمی‌شه. کد فقط با `env.AUTH_KEY` بهش رفرنس می‌ده؛ مقدار واقعی رو جدا و از طریق پنل Cloudflare تعریف می‌کنید.

۱. یک رشته‌ی تصادفی و امن بسازید. ساده‌ترین راه: داخل خود اپ اندروید، دکمه‌ی زیر رو بزنید:

```
🔑 ساخت کلید تصادفی و کپی
```

این دکمه یک کلید ۶۴ کاراکتری امن می‌سازه و خودکار کپی می‌کنه.

۲. توی داشبورد Cloudflare، وارد صفحه‌ی همون Worker بشید و این مسیر رو دنبال کنید:

```
Settings → Variables and Secrets → Add
```

۳. مقادیر زیر رو دقیقاً همین‌طور وارد کنید:

```
Type: Secret
Name: AUTH_KEY
Value: (کلیدی که کپی کردید)
```

۴. دکمه‌ی `Save and deploy` رو بزنید.

این کلید رو جایی امن نگه دارید — دقیقاً همینو باید توی اپ اندروید هم وارد کنید.

## مرحله‌ی ۳ — ساخت ریپازیتوری در GitHub

۱. وارد این آدرس بشید:

```
https://github.com
```

۲. یک ریپازیتوری خالی جدید بسازید (بدون افزودن README یا gitignore).

### تنظیم هویت git (قبل از هر commit لازمه)

اگه اولین‌بارتونه که از `git` روی این سیستم استفاده می‌کنید، قبل از هر کاری باید بهش بگید اسم و ایمیلتون چیه — وگرنه موقع commit با خطا مواجه می‌شید. توی ترمینال این دو خط رو بزنید (فقط یک‌بار لازمه، برای همیشه ذخیره می‌مونه):

```
git config --global user.name "اسم خودتون"
git config --global user.email "ایمیل خودتون"
```

اسم و ایمیل می‌تونه هرچی باشه، لازم نیست دقیقاً با اکانت گیت‌هابتون یکی باشه؛ فقط برای ثبت توی تاریخچه‌ی commitهاست.

### ساخت Secretهای لازم برای Cloudflare (قبل از آپلود پروژه)

پروژه برای دیپلوی خودکار Worker به دو تا Secret نیاز داره. بهتره همین الان، قبل از آپلود فایل‌ها، بسازیدشون تا وقتی فایل‌ها رو push کردید، ورک‌فلوها بدون مشکل اجرا بشن.

۱. یک API Token در Cloudflare بسازید:

```
https://dash.cloudflare.com/profile/api-tokens
```

روی `Create Token` بزنید، تمپلیت `Edit Cloudflare Workers` رو انتخاب کنید (یا Custom Token با دسترسی `Account → Workers Scripts → Edit`)، و در آخر `Create Token` رو بزنید. رشته‌ی تولیدشده رو کپی کنید (فقط یک‌بار نشون داده می‌شه).

۲. شناسه‌ی حساب (Account ID) خودتون رو پیدا کنید — توی صفحه‌ی اصلی داشبورد Cloudflare، کنار هر اکانت (مثلاً Workers & Pages) نمایش داده می‌شه.

۳. توی همون ریپازیتوری خالی که ساختید، این مسیر رو دنبال کنید:

```
Settings → Secrets and variables → Actions → New repository secret
```

۴. دو Secret زیر رو بسازید:

```
CLOUDFLARE_API_TOKEN → (توکنی که ساختید)
CLOUDFLARE_ACCOUNT_ID → (شناسه‌ی حسابتون)
```

### آپلود فایل‌های پروژه

حالا که ریپو ساخته شده، هویت git تنظیم شده، و Secretها اضافه شدن، نوبت آپلود فایل‌هاست. ساختار فایل‌ها باید دقیقاً همین‌طور باقی بمونه:

```
build.gradle
settings.gradle
gradle.properties
AndroidManifest.xml
cloudflare-worker.js
wrangler.toml
release.keystore
README.md
src/MainActivity.kt
src/ProxyService.kt
res/layout/activity_main.xml
res/values/colors.xml
res/values/strings.xml
res/drawable/...
res/mipmap-*/...
.github/workflows/build-apk.yml
.github/workflows/deploy-worker.yml
```

راحت‌ترین روش آپلود (چون پوشه‌ی مخفی `.github` با درگ-دراپ معمولی آپلود نمی‌شه)، استفاده از دستورات `git` در ترمینال است:

```
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

به‌جای `USERNAME/REPO.git` آدرس ریپوی خودتون رو بذارید.

نکته: گیت‌هاب دیگه رمز عبور معمولی رو برای `git push` قبول نمی‌کنه. باید یک Personal Access Token بسازید:

```
Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token
```

دسترسی `repo` رو تیک بزنید و رشته‌ی تولیدشده رو به‌جای پسورد وارد کنید.

## مرحله‌ی ۴ — دیپلوی Worker با Durable Object

یک Worker معمولی Cloudflare بعد از حدود ۳۰ ثانیه اتصال‌های طولانی‌مدت رو خودکار قطع می‌کنه — این یک محدودیت پلتفرمه، نه باگ کد. برای دور زدنش، Worker از یک Durable Object استفاده می‌کنه که نیاز به دیپلوی مخصوص (Wrangler) داره.

چون Secretهای لازم رو توی مرحله‌ی قبل از قبل ساختید، فقط کافیه بعد از push شدن فایل‌ها، به تب Actions ریپو برید و ورک‌فلوی زیر رو ببینید (باید خودکار اجرا شده باشه؛ اگه نه، دستی `Run workflow` بزنید):

```
Deploy Cloudflare Worker
```

این ورک‌فلو، Worker رو با تنظیمات Durable Object درست دیپلوی می‌کنه. بعد از این مرحله، دیگه نیازی به دست‌کاری دستی از داشبورد Cloudflare نیست.

## مرحله‌ی ۵ — ساخت apk اندروید

۱. توی تب Actions ریپو، ورک‌فلوی زیر رو پیدا کنید:

```
Build APK
```

اگه خودکار اجرا نشد، دکمه‌ی `Run workflow` رو بزنید.

۲. حدود ۳ تا ۷ دقیقه صبر کنید تا تیک سبز بخوره.

۳. از منوی سمت چپ همون صفحه، `Summary` رو باز کنید و پایین صفحه، بخش `Artifacts` رو پیدا کنید. فایلی با این اسم دانلود کنید:

```
TGRelay-arm64-v8a-release
```

۴. زیپ رو باز کنید — یک فایل `.apk` توشه.

۵. اون apk رو به گوشی منتقل کنید و نصب کنید. لازمه اجازه‌ی نصب از منابع ناشناس رو بدید.

این apk فقط برای معماری `arm64-v8a` ساخته می‌شه (اکثر گوشی‌های امروزی همینن).

---

## مرحله‌ی ۶ — استفاده از اپ

۱. اپ رو باز کنید.

۲. کلید مشترک (همون `AUTH_KEY`) رو وارد کنید — یا از دکمه‌ی `🔑 ساخت کلید تصادفی و کپی` استفاده کنید (فقط برای اولین‌بار، بعد باید توی Cloudflare هم ثبتش کنید).

۳. آدرس Worker رو وارد کنید، بدون `https://`، فقط چیزی شبیه:

```
tgviaandroid.your-username.workers.dev
```

۴. پورت رو `1080` بذارید (یا هر عدد دلخواه).

۵. دکمه‌ی `فعال کردن` رو بزنید. اپ اول یک تست سریع به Worker می‌زنه؛ اگه کلید یا آدرس اشتباه باشه، همون‌جا خطای واضح نشون می‌ده.

۶. وقتی وضعیت به `فعال` رسید (نقطه‌ی سبز)، دکمه‌ی `✈️ باز کردن در تلگرام` رو بزنید — دیالوگ افزودن پروکسی SOCKS5 با مقادیر پرشده باز می‌شه، فقط تأیید کنید.

اگه دکمه کار نکرد، این مسیر رو دستی توی تلگرام دنبال کنید:

```
Settings → Data and Storage → Proxy → Add Proxy → SOCKS5
```

مقادیر:

```
Server: 127.0.0.1
Port: (همون پورتی که توی اپ گذاشتید)
```

## عیب‌یابی

### اپ می‌گه «کلید مشترک اشتباهه»

مقدار `AUTH_KEY` توی اپ با مقداری که در Cloudflare (بخش `Variables and Secrets`) ثبت کردید یکی نیست. دقت کنید فاصله یا خط جدید اضافه در کلید نباشه.

### اپ می‌گه «آدرس Worker درست نیست»

یا آدرس رو اشتباه تایپ کردید، یا هنوز نسخه‌ی جدید `cloudflare-worker.js` رو دیپلوی نکردید.

### اپ می‌گه «اتصال به Worker برقرار نشد»

اینترنت گوشی رو چک کنید. اگه بازم تکرار شد و خطا از سمت یک اتصال تکی (نه کل اپ) بود، نگران نباشید — تلگرام معمولاً خودش دوباره امتحان می‌کنه.

### تلگرام روی «Connecting» می‌مونه

معمولاً یعنی Durable Object درست تنظیم نشده (مرحله‌ی ۴ این راهنما رو دوباره چک کنید).

برای دیباگ دقیق‌تر، لاگ زنده‌ی Cloudflare رو ببینید:

```
Workers & Pages → Worker خودتون → Logs → Begin log stream
```

بعد توی اپ «فعال کردن» بزنید و توی تلگرام سعی کنید وصل بشید؛ هر خطایی که توی لاگ ظاهر شد رو بررسی کنید.

## نکات فنی

- ترافیک هر بسته با مقدار تصادفی padding (بین ۰ تا ۶۳ بایت) بزرگ‌تر می‌شه تا الگوی ثابت پروتکل MTProto کمتر قابل‌تشخیص باشه. این padding فقط بین اپ و Worker وجود داره و قبل از رسیدن به تلگرام حذف می‌شه.
- این روش فقط ترافیک تلگرام رو عبور می‌ده، نه کل گوشی رو — باتری و دیتای بقیه‌ی اپ‌ها درگیر نمی‌شه.
- بعضی‌وقت‌ها تلگرام سعی می‌کنه از طریق IPv6 وصل بشه که Cloudflare اون رو به‌خاطر یک محدودیت امنیتی خودش رد می‌کنه. این طبیعیه و مشکلی ایجاد نمی‌کنه، چون تلگرام خودکار روی IPv4 برمی‌گرده.
- اگه یک روز دامنه‌ی `workers.dev` هم فیلتر بشه، باید یک دامنه‌ی شخصی روی Cloudflare ثبت کنید و به‌جاش استفاده کنید.
- اپ حالا با یک امضای اختصاصی (release) به‌جای امضای موقت (debug) ساخته می‌شه — این باعث می‌شه هشدار شدید «App blocked to protect your device» که مخصوص اپ‌های امضاشده با کلید debug هست دیگه نیاد. با این حال، چون اپ از گوگل‌پلی نصب نمی‌شه، ممکنه بازم یک هشدار ملایم‌تر («این نوع اپ معمولاً باعث آسیب به گوشی می‌شه» یا مشابهش) ببینید که کافیه «Install anyway» رو بزنید — این طبیعیه و برای هر اپ نصب‌شده خارج از گوگل‌پلیه.
- اگه فکر می‌کنید کلید لو رفته، فقط کافیه مقدارش رو در Cloudflare عوض کنید و توی اپ هم آپدیت کنید — نیازی به دیپلوی Worker جدید یا تغییر آدرس نیست.
